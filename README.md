# MakeDesign.md

프로젝트에 투입할 **`DESIGN.md` 표준 세트를 저작하고 검토하는 레포**입니다.

애플리케이션 코드는 없습니다. 여기서 만든 문서 세트를 대상 레포의 `.agents/` 아래로 복사하면, 그 레포의 프론트엔드 에이전트가 이 세트를 유일한 기준으로 삼아 UI를 구현합니다.

## 왜 필요한가

에이전트에게 "예쁘게 만들어줘"라고 하면 매번 다른 결과가 나옵니다. 색상은 그때그때 하드코딩되고, 로딩 상태는 빠지고, 다크모드는 반쯤 깨집니다.

이 레포는 그 판단을 **문서로 고정**합니다.

- 색상·타이포·간격은 토큰 파일 하나에서만 나온다 → 임의 값이 끼어들 여지가 없다
- 모든 화면은 로딩/빈/에러/성공 4상태를 처리해야 한다 → 체크리스트로 강제된다
- 그 규칙들이 실제로 어떻게 보이는지 목업 HTML로 즉시 확인할 수 있다 → 리뷰가 추측이 아니라 관찰이 된다

## 구조

**최상위 폴더 하나 = 디자인 시스템 하나**입니다.

```
nhimc/                                          국민건강보험 일산병원 (첫 과제)
  DESIGN.md                                     디자인 철학·브랜드 언어 (SSOT, 프롬프트)
  design-docs/
    design-system-reference-llms.txt            디자인 토큰 (색상·타이포·간격·컴포넌트)
    ui-ux-guidelines.md                         UI/UX 평가 루브릭·상태 체크리스트
  generated/
    design-mockup.html                          전체 규칙을 한 화면에 시각화한 검토용 미러
    design-mockup.css                           목업 스타일 + 토큰 CSS 변수
```

| 파일 | 역할 | 여기에 쓰는 것 | 여기에 안 쓰는 것 |
|---|---|---|---|
| `DESIGN.md` | 철학·브랜드 언어 | 무엇을 지향하는가, 왜 그런가 | hex 값, 기능 명세 |
| `design-system-reference-llms.txt` | 토큰 SSOT | 모든 수치·hex·컴포넌트 스펙 | 철학, 평가 기준 |
| `ui-ux-guidelines.md` | 평가 기준 | 무엇을 만족해야 통과인가 | 구체적 색상값 |
| `design-mockup.html/css` | 검토용 미러 | 위 규칙의 시각화 (목업 데이터) | 실제 API, 새 디자인 결정 |

### 대상 레포로 옮길 때

`.agents/` 접두사만 붙고 그 아래 구조는 동일합니다.

| 이 레포 | 대상 레포 |
|---|---|
| `nhimc/DESIGN.md` | `.agents/DESIGN.md` |
| `nhimc/design-docs/*` | `.agents/design-docs/*` |
| `nhimc/generated/*` | `.agents/generated/*` |

## 핵심 규칙: 소스 세트는 항상 일치한다

네 파일은 서로의 거울입니다. **하나만 고치면 시스템이 깨집니다.**

```
DESIGN.md  ←→  design-system-reference-llms.txt  ←→  ui-ux-guidelines.md
                              ↕
                   design-mockup.html / .css
```

- 토큰 값을 바꾼다 → **토큰 파일 먼저**, 그다음 `design-mockup.css`
- DESIGN.md 조항을 바꾼다 → 목업의 대응 섹션도 함께
- 목업에 새 값이 필요하다 → 토큰 파일에 먼저 추가한 뒤 참조 (역순 금지)

목업의 각 섹션에는 우측 상단에 `[DESIGN.md §x]` 태그가 붙어 있어 어느 조항의 시각화인지 1:1로 추적됩니다.

## 검토 방법

빌드도 테스트도 없습니다. **목업을 브라우저로 열어 눈으로 봅니다.**

```bash
# 로컬 서버로 열기 (CSS가 분리되어 있어 file:// 로는 일부 브라우저에서 막힐 수 있음)
cd nhimc/generated
python -m http.server 8000
# → http://127.0.0.1:8000/design-mockup.html
```

확인할 것:

1. 우측 상단 **다크모드 토글**로 두 테마 모두 볼 것 — 라이트만 맞고 다크가 깨지는 경우가 흔합니다
2. 창 너비를 375 / 768 / 1440px로 줄여볼 것
3. Tab 키로 순회하며 포커스 링이 모든 요소에 뜨는지 볼 것

### 피드백 방법

목업에서 마음에 들지 않는 부분을 찾으면, 해당 섹션의 `[DESIGN.md §x]` 태그를 인용해 의견을 주세요.

> `[DESIGN.md §3] + 카드 그리드가 너무 촘촘하다. 섹션 간 여백을 더 주자.`

그 태그를 근거로 `DESIGN.md`의 해당 조항을 수정하고, 토큰과 목업을 함께 갱신합니다. **목업을 직접 고치는 게 아니라 규칙을 고칩니다.**
